Módulo Catálogo — referencia de frontend

Equipo B · Vue 3 · Ciclo 2. Wireframe de las tres vistas a construir, anotado con los endpoints del contrato v2.2 que alimenta cada una.

Cómo leer este documento: los recuadros con borde punteado morado no son parte de la interfaz — son las reglas del contrato que esa pantalla debe respetar. El diseño visual es libre; lo que no se negocia es el comportamiento anotado.

Contrato

  • Consume GET /productos y GET /categorias (para el dropdown).
  • Parámetros: categoria, pagina, tamanoPagina (entre 1 y 100).
  • La primera página es la 1, no la 0. Es el error más fácil de cometer aquí.

  • Una categoría inexistente devuelve 200 con lista vacía, no un error: mostrar estado vacío, no pantalla de error.
  • Cada tarjeta enlaza al detalle usando el id del producto.

3. Formulario de administración

F3

Sirve para crear y para editar. En edición precarga todos los campos actuales.

/catalogo/admin/nuevo
Máximo 120 caracteres
El precio debe ser mayor que 0
Puede ser 0
Opciones desde GET /categorias
Opcional, una o varias URLs
Opcional

Contrato

  • Crear: POST /productos → 201. Editar: PUT /productos/{id} → 200. Desactivar: DELETE /productos/{id} → 204.
  • PUT reemplaza el producto completo. El formulario debe enviar todos los campos, no solo los que cambiaron: si falta un campo obligatorio, el backend responde 400 (VALIDACION_FALLIDA); si falta uno opcional (descripción o imágenes), ese dato se borra.
  • id y activo se ignoran si van en el cuerpo: el estado solo lo cambia DELETE.
  • Validar en el cliente lo mismo que valida el contrato (precio > 0, stock ≥ 0, nombre ≤ 120, categoría existente), pero la validación real es la del backend: hay que manejar igual el 400 (VALIDACION_FALLIDA) que llegue.
  • Desactivar pide confirmación. Es idempotente: desactivar dos veces responde 204 igual, sin error.

Estados transversales

F1

Componentes compartidos por las tres vistas. Van primero: sin esto, F2 y F3 los improvisan cada uno por su lado.

Cargando

Mientras la petición está en curso. Un placeholder o spinner, consistente en las tres vistas.

Lista vacía

No hay productos con ese filtro. Invita a cambiar la categoría; no es un error.

No encontrado

404 PRODUCTO_NO_ENCONTRADO. Mensaje claro y vuelta al listado.

Error de validación

400 VALIDACION_FALLIDA. Mostrar el mensaje del backend junto al formulario.

Sin conexión

El servicio no responde. Distinto de un 404: aquí ofrecer reintentar.

Criterios de entrega

  1. Las tres vistas navegables entre sí con Vue Router.
  2. Todo consume los endpoints reales a través de Kong. Se puede desarrollar contra datos simulados, pero el demo final no.
  3. La URL base del backend va en variable de entorno, no escrita en el código.
  4. Los cinco estados transversales implementados y usados por las tres vistas.
  5. Cada persona puede explicar por qué su vista se comporta así, citando el contrato.
